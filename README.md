## Highlights

- Moved a state agency's **Tier 2 RDMS dashboard refresh off manual Excel extracts** onto scheduled Python + SQL pipelines loading a SQL Server reporting layer
- Built **data quality gates on every load** (row counts, nulls, duplicate keys, sudden KPI swings) that halt the refresh, so bad data never reaches a published dashboard
- Designed the **star schema behind 20+ Power BI and Tableau dashboards** for finance, marketing and support, and moved the largest fact tables to **incremental loads** when full reloads outgrew the overnight window
- Built the **workforce data feed for a 280-agent support org**, joining scheduling, ticket and productivity data for staffing and shift planning
- Daily ETL from **Salesforce, Dynamics 365 and MySQL** into a SQL Server + PostgreSQL warehouse; Hadoop MapReduce jobs rolling raw logs into daily summary tables
- **Source-to-target mappings and a shared data dictionary** across three agency divisions; **PII masking and data lineage** for GDPR audits

## How I work

| | |
| --- | --- |
| 🧱 **Model first** | Agree on the grain and the metric definition before writing a single join. |
| ✅ **Test every load** | Data quality checks are part of the pipeline, not an afterthought. |
| 🔁 **Make it rerunnable** | Code in Git, CI/CD on Azure DevOps, run notes so anyone can rerun a failed load. |
| 🔒 **Protect the data** | PII masking, lineage, GDPR and FERPA-compliant handling by default. |
